## 模式一：交互模式（秀米链接）

### 用户输入格式

```
【标题】酒店/景区名称 价格 套餐概要
🆔编号：xxxxx
🚗房态：https://...（房态查询链接）
[烟花]抢购：https://...（抢购链接）
🎆秀米：https://...（秀米 H5 页面链接）
[红包]普返xx，深返xx（返佣信息）
下单编号：xxxxx
```

### 处理流程

1. **解析输入** → `parse_raw_input()`
   - 提取秀米链接、编号、房态链接、抢购链接、返佣信息、下单编号、标题行
2. **提取秀米内容** → `cmd_extract()` / `XiumiusExtractor.extract()`
   - 详见下方「秀米链接处理方法」
3. **生成套票列** → `generate_taopiao()`
   - 详见下方「套票列生成规则」
4. **提取内容列** → `extract_content_items()`
   - 从秀米原始内容中只保留以 `【】` 开头的套餐包含项行（如【住】【食】【玩】【赠】【享】【游】等）
   - 去掉价格、时间、加收等额外信息
5. **提取加收信息** → 从秀米内容中提取加收说明段落
   - 详见下方「加收列填写规则」
6. **交互填写** → `prompt_col_data()`
   - 提示用户填写酒店名、可上架渠道、售卖时间、可用日期、对外价格、直播价、头图等
7. **自动计算结算** → `calc_settlement()`
   - 详见下方「结算价格&利润率计算」
8. **写入飞书** → `append_row_by_cols()`

### 秀米链接处理方法

秀米 H5 页面（`a.xiumius.cn` / `v.xiumius.cn` / `c.xiumius.cn`）的内容通过 JavaScript 动态加载，直接请求页面 URL 只能拿到框架 HTML，完整内容在独立的 JSON 数据文件中。

**提取步骤：**

1. 用 `curl` 或 `web_fetch` 获取页面 HTML
2. 在 HTML 中查找 `injectedData.showInfo` 里的 `show_data_url` 字段，指向类似 `//sd.xiumius.cn/xmi/pd/xxx.json?_ver=xxx` 的 JSON 地址
   - `a.xiumius.cn` / `v.xiumius.cn`：`show_data_url` 直接出现在 HTML 中
   - `c.xiumius.cn`：`showInfo` 被 `decodeURIComponent` 包裹，需先 URL 解码再解析 JSON
3. 拼接完整 URL（补上 `https:`）请求该 JSON 文件
4. 在 JSON 的 `cubes[].pages[].layers[]._comp._$raHTML` 字段中获取完整的页面文本内容
5. 从文本中提取套餐明细等目标信息

### 套票列生成规则

**格式：** `【主要卖点】酒店名称·酒店房型｜套餐权益1+权益2+权益3+等等`

#### 主要卖点推理规则（按优先级）

| 条件 | 主要卖点 |
|---|---|
| 标题包含"不加收" | **周末不加** |
| 标题包含"五一"+"一口价" | 51一口价 |
| 标题包含"五一" | 五一主推 |
| 标题包含"一口价" | 一口价 |
| 标题包含"秒杀" | 秒杀 |
| 标题包含"专场" | 专场 |
| 标题包含"特惠" | 特惠 |
| 标题包含"预售" | 预售 |
| 标题包含"暑期" | 暑期 |
| 标题包含"开园" | 开园 |
| 标题包含"含晚餐"或"含早" | 含餐 |
| 默认 | 主推 |

**注意：** "不加收"优先级最高，主要卖点为 **【周末不加】**（不是【不加收】）。

#### 套餐权益提取

从秀米内容中提取【住】【食】【赠】【畅】【玩】【享】【免】等标签行，取标签后的内容作为权益项，最多取前4个。

如果秀米内容中没有提取到权益，则从标题中提取 `+` 号连接的卖点作为后备。

#### 房型提取策略（按优先级）

1. 找"酒店"后面跟房型关键词（池景房/山景房/海景房/温泉房/别墅房/别墅/海景/房等）
2. 找"秒杀"后面的房型
3. 找"抢"后面的房型
4. 找"元"（或"￥"）后面的房型

**房型格式：** 房型应包含床型信息，如 `臻品大/双床房`（不是 `臻品房`）。

#### 卖点提取

从标题中 `+` 号连接的内容取前 **4** 个卖点。

**卖点前缀：** 如果套餐包含"2大2小"等人数信息，卖点应保留该前缀，如 `2大2小无限次汤泉`。

#### 酒店名

**不要**在酒店名前加地域前缀（如"清远·"、"惠州·"等），直接使用酒店全称。

- 正确：`英德奥园巧克力王国酒店月曜楼`
- 错误：`清远·巧克力王国·沐云·英德奥园巧克力王国酒店月曜楼`

#### 酒店名与房型分隔

酒店名和房型之间用 `·` 分隔。如果酒店名包含品牌/子名称也应用 `·` 分隔。

- 正确：`广州·钧明欢乐世界·城市精选酒店·高级房`
- 错误：`广州·钧明欢乐世界·城市精选酒店高级房`

#### 示例

- 标题：`￥568住南昆山大观园时尚风双床房+2大2小自助早餐+自助晚餐+无限次畅泡128式高硅酸钙温矿泉+...`
- 输出：`【主推】惠州南昆山·大观园·时尚风双床房｜2大2小自助早餐+自助晚餐+无限次畅泡128式温矿泉`

- 标题：`【广州·钧明欢乐世界】全年专场！平日周末不加收！￥378元住城市精选酒店高级房+世嘉乐园+索尼克乐园+穿越火线...`
- 输出：`【周末不加】广州·钧明欢乐世界·城市精选酒店·高级房｜世嘉乐园+索尼克乐园+穿越火线`

- 标题：`【清远·巧克力王国·沐云】平日周末不加收！水世界遛娃玩水，一站式安排！299元秒杀四星英德奥园巧克力王国酒店月曜楼（原沐云假日酒店）臻品房+无限次泉林汤泉+水世界+巧克力小镇+参观红旗茶厂+双人星鹿生态农场+越野车15分钟！`
- 输出：`【周末不加】英德奥园巧克力王国酒店月曜楼·臻品大/双床房｜2大2小无限次汤泉+水世界+巧克力小镇+越野车或儿童卡丁车`

### 内容列提取规则

从秀米提取的原始内容中，只保留以 `【】` 开头的套餐包含项行（如【住】【食】【玩】【赠】【享】【游】等），去掉价格、时间、加收等额外信息。

示例：
- 原始内容包含：`【住】高级双床/大床房1间1晚`、`抢购价：328元/套`、`售卖时间：即日起--售完即止`
- 内容列只保留：`【住】高级双床/大床房1间1晚` 等套餐包含项

### 加收列填写规则

- **J 加收列**：填写套餐本身的加收规则，如"周六加收70元/间"、"端午假期6月19日-20日需加收150元"
- **K 其他加收列**：填写可升级房型等额外加收，如"加200元/间升级酒店湖景房"
- **不要遗漏加收信息**。秀米"套餐包含"区域下方通常有"加收说明"或"加收"段落，需完整提取其中的加收规则原文。
- **常见错误**：之前多次遗漏加收信息（海滨温泉的端午加收120元、夏湾拿的周六加收30元/端午加收50元），都是用户手动指出后才补充。根本原因是只关注了套餐包含项，没有检查加收说明部分。

### 结算价格&利润率计算

**公式：**
- 基础结算价 = 直播价 - 深度返佣
- 基础利润率 = 深度返佣 / 直播价 - **8%**
- 加收结算价 = (直播价 + 加收金额) - 深度返佣
- 加收利润率 = 深度返佣 / (直播价 + 加收金额) - **8%**

**输出格式：**
```
结算价{基础结算价}；利润率{基础利润率}%（加收{金额1}结算价{结算价1}；利润率{利润率1}%；加收{金额2}结算价{结算价2}；利润率{利润率2}%）
```

**如果有多种加收（如周六加收30、端午加收50），每种都要分别计算并展示。** 传入 `calc_settlement` 的 surcharge 参数必须包含所有加收信息（如 `"周六加收30元/间；端午（6.19-6.20）加收50元/间"`），不能只传其中一种。

**注意：** 仅计算 **J 加收列**中的加收金额，**K 其他加收列**（如升级房型加收）不参与结算计算。

**示例：**
- 直播价 168，深度返佣 45，加收 70
- 基础：结算价 123，利润率 18.8%
- 加收70：结算价 193，利润率 10.9%
- 输出：`结算价123；利润率18.8%（加收70结算价193；利润率10.9%）`

- 多种加收示例：直播价218，深返35，加收30和50
- 输出：`结算价183；利润率8.1%（加收30结算价213；利润率6.1%；加收50结算价233；利润率5.0%）`

**加收金额匹配：** 加收列文本可能以不同格式出现：
- `"周六加收70元/间"` → 匹配 `加收(\d+)`
- `"周六+100元/套"` → 匹配 `+(\d+)`
- 正则：`(?:加收|[+])(\d+)`

### 售卖时间规则

如果秀米内容中「售卖时间」为"即日起--售完即止"或"即日起----售完即止"，则售卖时间直接填写与 **可用日期** 相同的内容。

## 模式二：海报模式（poster）

### 用法

```bash
python3 src/main.py poster <图片路径>
```

### 支持的图片格式

JPG、PNG、GIF、BMP、WebP、TIFF

### 处理流程

1. **OCR 识别** → `ocr_image()`（调用 tesseract，语言 chi_sim+eng）
2. **智能解析** → `parse_poster_text()`

   - 价格（匹配 ¥XXX元 / XXX元/套 等格式）

   - 加收信息（包含"加收"的行）

   - 可用日期（"使用时间"后面的内容）
3. **交互补充/修改**
4. **自动计算结算价**
5. **写入飞书**

### 海报OCR增强处理（手动模式）

当用户提供海报图片路径（如 `@享海假日:君廷.jpg`）时，按以下步骤处理：

#### 步骤1：检查OCR环境
```bash
which tesseract && tesseract --version
```
确认 tesseract 已安装且支持 `chi_sim` 简体中文包。

#### 步骤2：直接OCR识别
```bash
tesseract "<图片路径>" stdout -l chi_sim+eng --psm 6
```
- 使用 `--psm 6`（假设为统一文本块）模式
- 语言包 `chi_sim+eng`（简体中文+英文）

#### 步骤3：图片预处理（如直接OCR效果不佳）
如果直接OCR结果不理想（乱码、缺失关键信息），用Python+Pillow预处理：

```python
from PIL import Image, ImageEnhance, ImageFilter

img = Image.open(img_path)
# 放大3-5倍
w, h = img.size
img = img.resize((w*3, h*3), Image.LANCZOS)
# 转灰度
img = img.convert('L')
# 增强对比度
enhancer = ImageEnhance.Contrast(img)
img = enhancer.enhance(2.0)
# 锐化
img = img.filter(ImageFilter.SHARPEN)
img.save(tmp_path)
```

**注意：** 二值化处理（`img.point(lambda x: 255 if x > threshold else 0)`）可能会丢失细节，慎用。

#### 步骤4：解析OCR文本
从OCR结果中提取关键字段：

| 字段 | 提取方法 |
|---|---|
| 酒店名称 | 找"酒店"关键词或【】中的名称 |
| 标题/亮点 | 找【】中的亮点词（如618大促、秒杀等） |
| 直播价 | 匹配 `¥XXX元` / `XXX元/套` / `XXX元起` |
| 房型 | 找"房"前面的关键词（海景房/双床房/套房等） |
| 套餐包含项 | 找【住】【食】【赠】【玩】【免】等标签行 |
| 加收信息 | 找包含"加收"、"周末"、"平日"、"周六"等关键词的行 |
| 售卖时间 | 找"抢购日期"后面的内容 |
| 可用日期 | 找"使用日期"、"有效期"后面的内容 |

#### 步骤5：用户确认/补充
- 将解析结果展示给用户确认
- 用户补充缺失信息（如结算价、返佣、加收细节等）
- 用户修正OCR识别错误

#### 步骤6：写入飞书
按18列结构构建数据行并写入。

#### 常见问题
- **风景图叠加文字**：OCR识别效果差，需用户手动提供关键信息
- **价格识别**：海报上的价格可能被促销标签遮挡，需用户确认
- **加收信息**：海报上的加收规则通常以小字显示，OCR可能遗漏，需用户补充
- **日期格式**：OCR可能将"2026年"识别为"2026年"或"2026年"，需人工校正
